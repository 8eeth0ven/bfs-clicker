# 性能优化与验证记录

日期：2026-10-27。基线：`f085111e2f1f353e77a8f6ad8f2b7040f36232f1`。实现位于 `codex/performance-review` 工作区；没有推送。初始检查见 [性能审计](performance-review.md)，可读原始测量见 [performance-results.json](performance-results.json)。

## 实际改动

### 等待与状态快照

`dialogs.js` 观察请求、文档导航、DOM mutation、开放 Shadow DOM 和允许访问的 iframe。稳定结果按活动代次缓存；每次命中缓存前仍读取 DOM 版本。`replay.js` 在点击、hover、选择、滚动及直达操作前显式失效旧结果。同一稳定代次经过多个 helper 时不再重复等待。

默认 `quietMs + settleMs = 160ms` 作为连续观察窗，新 DOM/网络活动会重启静止计时；保留配置的总超时。`short` 使用 `min(400, timeoutMs)`，不再反而忽略较小的 timeout。没有把默认等待改成此前会漏控件的 20ms。动作后的指纹统一在最终稳定收集处计算，避免计算两份不同时点的快照。

这是有界观察，不能保证等待所有未来定时器、持续轮询或不可见状态变化。忽略噪声选择器和 frame 采样上限继续生效；closed shadow 仍不支持。

### 减少路径重放

`runner.js` 可以直接探索刚构建、仍驻留于当前页面的新状态；使用前重新验证完整语义指纹和可安全重放路径。深链无需每到一层便重返入口。

这个优化刻意收窄了复用条件：**执行任何动作前就废弃旧 resident；命中已有指纹时也不重新启用复用。** 因此无 DOM 变化的动作、被拒绝的确认框、被拦截的请求，仍在下一动作前恢复页面。隐藏 JS 状态可能变化，URL/DOM 相同不能证明业务状态相同。表单 `safeReplay=false` 的拒绝规则继续保留，不以 href 捷径代替真实事件处理器。

### 增量断点与证据恢复

`store.journal()` 把变更状态及元数据写入私有 `checkpoint.journal.jsonl`，每次追加后 fsync；每秒默认合并一次完整快照，最终结束强制合并。公开 checkpoint 在合并时发布，活跃进度仍由 run.json 提供。

顺序为先提交 journal，再 compact。journal 有身份、runId、递增序号和校验和；轮换保留 previous 快照所需的完整恢复窗口。截断末行会另存私有 rejected 文件并记恢复事件；中间损坏、校验/身份/序号不符会拒绝恢复。恢复时复制增量值，避免后续修改状态对象反向修改历史记录、使校验和失效。

runner 登记尚未提交的脏状态；即使新状态插入后截图/DOM 采集异常，异常或最终保存也会把父子状态一起提交。恢复会重建 frontier，已经发现却尚未 enqueue 的状态不会丢失。

`evidence.restore()` 流式扫描原始 events/traffic，重建上次快照之后的尝试、观察、失败、静态候选、请求来源和摘要；不用 response ID 作时间截点，避免漏掉晚到正文。原始记录全部保留，重复恢复不重复累加样本。恢复启动成本随历史日志规模增加；未将其宣称为大日志恢复提速。

SIGKILL 发生于实际动作生效之后、结果提交之前时，仍可能重排尚未提交的动作；这不是外部副作用 exactly-once 承诺。非安全表单路径不会自动重放。

### 正文采集与导出

默认图片、字体、媒体和其他二进制响应只保留元数据，避免占满 HTML/JS/API 正文池。需要二进制归档时可显式设置 `captureBinaryBodies:true`；仍受长度、队列和正文预算限制。HAR 标明正文省略原因、请求证据关联、响应摘要与动作来源；公开 HAR 继续移除正文并脱敏。

正文队列优先处理文本；队列满时可挤出尚未开始的低优先级归档项，保留明确原因。超时不再提前释放底层 body 读取槽，物理未完成读取不超过 `maxBodyConcurrency`。drain 保持有界，并记录未完成读取；关闭浏览器后再次排空。

未知 Content-Length 仍只记元数据。Playwright 解码缓冲不能视作严格字节硬上限。`captureTraffic:false` 会省略无挖掘用途的正文，但仍为 HTML/JS/JSON 提取端点。

### 种子公平调度

显式 seedRoutes 在宽 UI 前沿前获得机会；自动发现种子默认每 8 个新动作插入一次，避免 UI 持续扩展时种子永远排不到。访问种子后仍通过 reach 恢复原 UI 状态。普通导航失败记 coverage gap 并继续 UI，预算、认证和关键守卫故障仍传播停止。Chromium 在失败后可能延迟提交错误页，恢复派发前先观察该过渡，避免下一次正常导航被打断。

## 第一轮含图版本的同条件浏览器基准

macOS arm64，Node v26.8.1，Playwright 1.64.1，Chromium 156.0.8078.4。基线源码由 `git archive f085111` 提取，使用相同依赖。每场景每版本三轮，轮次反转版本顺序；浏览器/字体先预热。保留双方默认 PNG 截图、50ms 请求间隔、safe 动作策略和完整守卫。优化版默认开启浏览器发起栈采集，并生成完整 JSON/DOT/交互图；基线没有这些功能。耗时包括启动、采集、图与报告导出、关闭。

| 本机夹具 | 每轮相同覆盖 | 基线平均 | 优化平均 | 吞吐提升 |
| --- | --- | --- | --- | --- |
| 分叉树 | 7 状态、9 个成功动作、7 个 observed API | 12.319s | 10.048s | 1.23 倍 |
| 六层深链 | 7 状态、6 个成功动作、7 个 observed API | 11.536s | 3.226s | 3.58 倍 |
| 120ms 延迟链接 | 3 状态、3 个成功动作、2 个 observed API | 3.319s | 2.663s | 1.25 倍 |

这一阶段含图版本的 18 轮均 completed；当时采集/构图 src 源码 SHA-256 与测量时记录逐文件核对一致。此前两个性能实现轮次另跑过 36 轮对照，提速方向一致；本表采用该阶段含图完整功能的最终一轮数据。每场景的完整状态指纹集合、URL 路径、成功动作数和实际观察到的 API 集合一致。只比较 observed API，未把静态候选混入实际接口覆盖。优化版每轮额外核对图中的状态/API集合与原始采集一致；小夹具图构建及导出本身约 4.5–18.5ms。

深链每轮请求 **56→14**，重放动作 **15→0**；动作预算计数 **21→6**。分叉树仍需要恢复不同父页面，收益低于深链；没有为了更高数字放宽隐藏状态隔离。结果仅对应这些本机夹具，不代表所有真实站点的提速倍数。

## 存储规模微基准

1000 个合成状态、每状态 50 个动作，共更新一个状态 50 次。两组每次都先写相同 journal 并 fsync；对照每次另做完整 compact，优化组最后 compact，均验证恢复图和计数一致。初始建图/快照不计时，最终 compact 计时。

| 项目 | 每次全量 compact | 增量 + 最终 compact |
| --- | --- | --- |
| 总存储时间 | 14.817s | 0.434s |
| 逻辑写入量，含公私副本/备份/轮换 | 2.624 GB | 53.3 MB |
| 文件 fsync | 200 次 | 53 次 |
| 目录 fsync | 150 次 | 3 次 |

这是单次局部存储测量，有顺序/缓存/文件系统误差，不可把约 34 倍局部比值当成整站吞吐提升。

## 配置与运行

| JSON 配置 | 默认 | 合同 |
| --- | --- | --- |
| checkpointIntervalMs | 1000 | 正整数；合并完整快照的间隔，动作增量仍逐次 fsync |
| reuseVerifiedState | true | 仅复用刚构建且重新验证过的状态；false 可关闭此优化 |
| seedInterleaveActions | 8 | 正整数；自动发现种子插入间隔 |
| captureBinaryBodies | false | 显式开启二进制归档；不保证一定存下超预算正文 |

没有改默认请求间隔、截图格式、动作/请求范围、logout 拦截、凭证隔离和预算上限。`maxTabs` 仍是页面数量上限，本次没有把它包装成并发 worker。

```sh
npm ci
npx playwright install chromium
npm test
npm run benchmark

# 已保留并安装依赖的基线源码可用于对照
npm run benchmark -- --baseline /path/to/baseline/src/runner.js --repeats 3
```

benchmark 只启动 localhost 夹具，输出到独立 output-performance 目录，任何一轮未完成或状态/API 覆盖不一致都会失败。完整结果记录版本标签、引擎、每轮数据、重放与持久化计数。

## 验收范围

回归测试已真实随仓库新增，以 Node 内置运行器执行；移除原来指向缺失脚本/Python 文件的测试命令。单元覆盖配置、策略、脱敏、URL/API、HAR、等待、正文池、增量恢复；集成覆盖真实请求守卫、凭证隔离、429、请求预算、深链/隐藏状态、种子、断点续跑、SIGKILL、父子故障、报告失败、iframe/shadow/hover/滚动/forms；E2E 覆盖真实 DOM 观察和面板新建/续跑/报告保护。

性能阶段连续两次完整 npm test 为 82 PASS / 0 FAIL；扩展网站图后，该阶段完整回归为 129 PASS / 0 FAIL（88 单元、26 集成、15 E2E），另有前轮 126 项通过记录。累计三轮共 54 次浏览器基线对照保持相同状态与 observed API 覆盖。新增故障先复现再修复，采集/构图源码摘要与基准逐文件一致，查看器已在最后筛选修正后完成真实浏览器复测；npm pack --dry-run 确认新模块/基准脚本和结果文档被打包、私有测量产物未被包含。没有用历史文档中的 PASS 数代替本轮执行。Windows/Linux、其他 Node 版本和真实业务大站长跑尚未在本机验收。遗留的无全局上限账本、未知长度正文、closed shadow、任意延迟 JS 因果归因等限制仍存在。

## MCP 与图查看器第二轮

2026-10-27 新增官方 SDK v2 的本地 stdio MCP，共 12 个工具，覆盖后台启动/停止/续跑、状态/列表、离线重建及图摘要/分页/邻域/路径。worker 使用现有守卫与断点存储；owner+PID逐次校验阻止跨实例误停。IPC断连取消与20秒看门狗覆盖客户端强杀服务进程的情形。接入方式与工具合同见 [MCP说明](mcp.md)。

图查看器为状态、路径、搜索及严格观察边建立索引；选择只更新样式，保留SVG和平移缩放；最近8个视图使用LRU。按真实关系组织分页，使5000节点/8198边样本首屏在120节点上限内显示137条关系；同向平行边、自环与返回边分别走独立通道，context仍不会成为确证路径。

相同5000节点输入五轮本机对照，选择处理加布局中位约7.4→0.6ms，热筛选约4.8→3.1ms。两版首屏内容不同（旧版零边，新版137边），不能把这些局部交互数字当作同内容归一化或整站吞吐倍数；亚毫秒测量只给近似值。原始样本和源码SHA记录在性能结果JSON的viewerV2中。

MCP图查询限制输入128MiB、节点100000/边300000；最多缓存2份图，按mtime/ctime/size/ino/dev失效。分页最多100条、邻域最多200节点和200条边，逻辑JSON响应最多128KiB，超过后显式返回省略/缺口。12000节点/11999边、3.76MB图样本预热后30次分页只读取并建索引1次，具体耗时见结果JSON的mcpGraphQuery；这是查询函数耗时，不含MCP协议及模型处理。

最终完整 `npm test`：**183 PASS / 0 FAIL**（88单元、26集成、18 E2E、51 MCP/生命周期）。MCP组包含官方客户端两代协议发现、真实localhost爬取与图查询、离线重建、停止续跑、跨连接停止隔离、重连、EOF保存、导航中SIGKILL父进程、预算建立前断连及卡住worker看门狗。新图浏览器测试验证真实有边5000节点、选择零SVG替换、缩放不跳、多边/自环独立、分页/候选/上下文语义。macOS/Node26为本次执行环境，未扩大为其他平台已验证的声明。
