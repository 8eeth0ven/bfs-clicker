# 视觉字段分区研究

这里保存实验策略，不提供 MCP 能力，也不随生产 npm 包发布。`visual-field-partitions.js` 没有接入观察器、Python 工作流、能力目录或生成入口；旧 OCR、`regions`、`nativeText` 规则没有因此升级权限。

已确认的限制是：真实绘制的 `上 海`，被 Vision 的完整画面和局部区域同时识别为 `上海`。在只声明 query label/value 两个字段的新策略下，算法接受了该识别结果，和已知绘制源不相等。代码没有删除这个空格；引擎输出已经遗漏了 U+0020。当前像素覆盖证明不能恢复或证明原应用字符串中的空格。

最初四字段策略还受到无关拒绝的混淆：四张实际反例图的 `RESULT` 局部候选置信度都是 0.5，低于固定 0.6 门槛，足以让整帧拒绝。这些拒绝不能算作空格或后缀保护的针对性通过。用相同原件、另一个明确声明的两字段策略复验后：

| 已知绘制值 | 结果 |
|---|---|
| `NotQuery` | 接受，完整保留 `NotQuery`，没有变成 `Query` 后缀 |
| `Not搜索` | 接受，完整保留 `Not搜索`，没有变成 `搜索` 后缀 |
| `上 海` | 接受为 `上海`，准确性条件失败 |
| 引号及标点样本 | 因原候选标点覆盖冲突而拒绝 |

两字段复验使用新策略和新 revision，保留 `RESULT` 为完整的范围外父候选，没有新增识别调用或修改原件。四张新渲染图共进行了 20 次固定、单线程识别；未按结果追加轮次、降低门槛或清洗文字。

策略研究包括显式本地 owner 字段/背景声明、完整原候选及词范围、连通分量全覆盖、可核验背景像素带和有界读取/运算。空字段也必须显式允许，区域确无前景且没有 full/regional 文本冲突，并保存独立 empty proof，不能用空 token 代替证明。这些条件可以检查部分几何与证据一致性，不能证明控件角色、业务结果或 source-string 精确性。

源码中的策略声明不等于真实动作授权。当前代码只作研究，尚无该策略的真实工作流或设备 MCP 闭环验收。纯色背景、横向分区等适用条件也不能推广到任意网站或应用。

可运行实现与预算检查：

```sh
node --test test/visual-field-partitions.test.mjs test/visual-field-partitions-vision.test.mjs
```

前者主要使用合成像素/候选检查合同，不是 OCR 准确率评测；后者检查 Swift 参数及错误分支，不进行像素识别。macOS 上需要现有 Xcode/Swift 与 Vision。实际原图、原生输出及独立复核证据留在私有研究产物中，不随本目录发布。

生产 Swift 辅助程序保留显式 `--field-evidence` 结构诊断标志；未带标志时旧输出不变。该标志没有为本实验开放 MCP 策略入口。
